🖥 Infrastructure

Gérer les plateformes

Administration dit quels outils ce projet utilise et avec quels accès. Infrastructure décrit ce que chaque outil sait faire : sa spécification d'API, et les opérations qu'on en retient. Importez une spécification par son URL ou depuis un fichier — aucun fichier de configuration à toucher.

Outils

Spécification d'API
Le serveur va chercher la spécification lui-même — un navigateur en serait empêché par la politique d'origine croisée. OpenAPI 2 ou 3, en JSON. Si l'URL est sur le même hôte que la connexion de cet outil, ses identifiants sont joints : une spécification protégée reste lisible.
En repli, une URL de documentation fait l'affaire (index llms.txt ou page Markdown) : APS recolle les fragments OpenAPI qu'elle contient.
Sonde les emplacements habituels à partir de l'URL de la connexion.
Serveur MCP
Un serveur MCP annonce lui-même ses outils : ni URL de spécification à chercher, ni format à reconnaître. Il faut seulement une connexion de type MCP pour cet outil, avec l'URL du serveur et son jeton — à créer dans Administration › Connexions.
Opérations
Contexte de test
Des valeurs nommées qui remplissent les paramètres pendant un test. Sans elles, la plupart des opérations sont hors de portée : sur une API orientée ressources, presque tout exige un identifiant. Seuls les paramètres requis sont envoyés — en joindre d'autres casse certains appels.
Une opération décrit un appel HTTP. Une façade APS décrit un verbe métier, qui vaut parfois plusieurs appels. Ce qu'on retient ici est un choix, pas un déversement.
